# AI 日报内网同步方案

## 整体架构

```
目标网站 (aihot.virxact.com)
        │ 每天 09:00 GitHub Actions 定时抓取
        ▼
GitHub 仓库 (ai-daily-hub)：JSON 数据文件 + 爬虫脚本
        │ 每天 09:30 公司内网服务器从 raw.githubusercontent.com 拉取
        ▼
内网动态 Web 应用 (Flask + SQLite)：日报/周报/月报展示
```

## 第一部分：GitHub 仓库（数据中转站 + 爬虫）

仓库结构：
```
ai-daily-hub/
├── .github/workflows/crawl.yml   # 定时工作流
├── crawler/
│   ├── crawl.py                  # 主爬虫
│   ├── parse.py                  # HTML 解析（requests + BeautifulSoup）
│   └── requirements.txt
├── data/
│   ├── index.json                # 清单：所有已抓取的日/周/月报日期列表
│   ├── daily/2026-07-30.json     # 每日一期：分类、标题、摘要、来源、详情页链接
│   ├── weekly/2026-W30.json
│   ├── monthly/2026-07.json
│   └── items/<id>.json           # 每条新闻全文（Markdown 正文、AI摘要、评分、原文链接）
└── intranet-app/                 # 内网应用代码（见第二部分）
```

**爬虫逻辑（crawl.py）**：
1. 抓取 `/daily/当天日期` 页面 → 解析出分类（模型发布/产品/行业动态/论文/技巧观点）、每条新闻的标题/摘要/来源/详情链接，存为 `data/daily/<date>.json`
2. 对日报中每个 `/items/<id>` 链接，若 `data/items/<id>.json` 不存在则抓详情页（优先尝试页面上的 Markdown 导出入口，退化为解析 HTML 正文），提取全文、AI 摘要、评分、原文链接
3. 周报/月报：抓取 `/weekly`、`/monthly` 索引页，发现 `index.json` 里没有的新期号就抓对应 `/weekly/YYYY-Www`、`/monthly/YYYY-MM` 页面（同样含每条新闻全文抓取）
4. 更新 `index.json` 清单，workflow 自动 `git commit && push`
5. 细节：带 User-Agent、每次请求间隔 1 秒、失败重试 2 次；解析失败时 workflow 报错（GitHub 会邮件通知）

**定时工作流（crawl.yml）**：
- `schedule: cron '0 1 * * *'`（UTC 01:00 = 北京时间 09:00）+ `workflow_dispatch` 支持手动触发
- 步骤：checkout → 安装 Python 依赖 → 运行 crawler → 提交 data/ 变更
- 注意：GitHub 定时任务可能延迟几分钟，09:30 拉取留有足够缓冲；日报本身是早 8 点发布，时间充裕

## 第二部分：内网动态 Web 应用（Flask + SQLite）

放在同一仓库的 `intranet-app/` 目录，部署到公司内网服务器：

```
intranet-app/
├── sync.py            # 数据同步脚本
├── app.py             # Flask 应用
├── db.py              # SQLite 建表与读写
├── templates/         # 日报/周报/月报/详情页模板（仿原站布局）
├── static/
└── requirements.txt
```

**同步脚本（sync.py）**，内网服务器 cron 每天 09:30 执行：
1. 从 `https://raw.githubusercontent.com/<你的用户名>/ai-daily-hub/main/data/index.json` 拉取清单
2. 与本地 SQLite 对比，只下载新增的 JSON 文件并入库（幂等，重复执行安全）
3. 失败自动重试；若 raw 域名某天不通，降级尝试 GitHub Pages 镜像地址

**Web 应用页面**：
- 首页三个 Tab：日报 / 周报 / 月报（仿照原站设计）
- 日报页：左侧按月归档的日期列表 + 右侧当日内容（今日看点目录、分类分节、每条新闻卡片）
- 新闻详情页：全文、AI 摘要、评分、原始来源链接
- 周报页：本期主线 + 分主题看点；月报页同理
- 附加：按日期归档浏览、标题关键词搜索

**部署**：Python 3 + waitress（或 gunicorn）常驻运行，可选 nginx 反向代理；crontab 加一行 `30 9 * * * python /path/sync.py`。

## 实施步骤

1. 在家中电脑创建仓库骨架，编写并本地跑通爬虫（验证能正确解析日报/周报/月报/详情页）
2. 配置 GitHub Actions 工作流，手动触发一次验证自动抓取+提交；观察次日 09:00 定时运行结果
3. 编写 Flask 内网应用和 sync.py，在家中用同一 GitHub 仓库测试同步与页面展示
4. 将 `intranet-app/` 部署到内网服务器，配置 cron 09:30 同步，验证内网访问

## 注意事项
- 解析依赖目标站当前 HTML 结构，若对方改版需更新 parse.py（workflow 失败会有邮件提醒）
- 每天抓取约 20-30 个详情页，已加延时避免给对方服务器造成压力
